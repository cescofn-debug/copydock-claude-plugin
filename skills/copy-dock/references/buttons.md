# Buttons, links and calls to action

A button is a promise about what happens when it's pressed. Keep the promise.

## Rules

- **Start with a verb** and name the object when it isn't obvious: "Create project", "Send invite", "Download report".
- **Say exactly what happens.** "Delete project" beats "Confirm". "Save and continue" beats "Next" when it saves.
- **Sentence case**, no full stop, usually 1 to 3 words, rarely more than 5.
- **Avoid** "OK", "Submit", "Yes/No", "Click here", "Learn more" without context. If "Learn more" is the only option, add what about: "Learn about roles".
- **Match the heading or question.** A dialog titled "Delete project?" has buttons "Delete project" and "Cancel".
- **Destructive actions** say what they destroy, and the safe choice is the default focus.
- **Consistent pairs** across the product: "Cancel" (not "Close" in one place and "Dismiss" in another).
- **Links** say where they go: "Read the privacy policy", "View all invoices". Never "here".
- **Calls to action** on marketing pages name the outcome or the next step: "Start writing", "Book a demo", "See pricing". Not "Get started" everywhere.
- **States:** a loading button says what it's doing ("Saving…"); after success, the result appears in the UI or a toast, not in the button forever.

## Examples

| Don't | Do |
| --- | --- |
| Submit | Send request |
| OK | Got it (for acknowledgement) or the real action |
| Yes | Delete 3 files |
| Click here | Download the report |
| Get Started Now! | Create your first project |
